# Семейное приложение для учебных карточек

Спецификация от 10 октября 2026 года. Актуальный вариант — самостоятельная мобильная веб-аппликация на сервере пользователя.

Приложение предназначено для дочки и нескольких близких пользователей. Оно сохраняет учебные материалы, создаёт карточки и тесты по выбранным темам, объясняет ответы простыми словами и хранит личную историю занятий. Развёртывание выполняется через Docker Compose.

## Согласованные требования и рабочие решения

Согласованы Python для бэкенда, React для фронтенда, использование shadcn/ui, форма входа и Docker. Пользователь допускает SQLite либо отдельную базу MySQL. Для первой версии предлагается SQLite в постоянном Docker volume: один экземпляр приложения, несколько пользователей и небольшой объём записей. MySQL потребовал бы отдельного контейнера и обслуживания базы; переход к нему не входит в первую версию.

Подтверждённая структура библиотеки: **предмет → темы → карточки**. Отдельная таблица **users** хранит пользователей. Документы относятся к теме как источники; они не образуют дополнительный уровень между темой и карточками.

Рабочее решение для семейного использования: все созданные владельцем аккаунты видят общую библиотеку предметов, тем и материалов. История занятий и прогресс принадлежат конкретному аккаунту. Владелец создаёт отдельные аккаунты себе и дочке. Публичной регистрации нет.

Ранее рассматривавшиеся проекты ChatGPT и сервер MCP заменены самостоятельным приложением. Облачные сервисы хостинга не требуются: пользователь размещает Docker-контейнер на своём сервере.

## Стек и развёртывание

- FastAPI, Python, Uvicorn — HTTP API, интеграция OpenAI и раздача собранного фронтенда.
- SQLAlchemy и Alembic — модели данных и версионируемые миграции SQLite.
- React, TypeScript, Vite, shadcn/ui — адаптивный интерфейс.
- OpenAI Responses API с настраиваемой моделью; по умолчанию `gpt-6-luna`.
- Structured Outputs для всех ответов модели: строгая JSON Schema, определённая типами Pydantic на бэкенде.
- Dockerfile с этапом сборки React и конечным Python-образом. Node.js используется только при сборке фронтенда, не как бэкенд или процесс на сервере.
- Один сервис Docker Compose, один процесс Uvicorn и один постоянный volume `/data` для SQLite, оригиналов документов и служебных данных.

Приложение и API находятся на одном origin. Docker публикует порт приложения на loopback хоста для подключения существующего reverse proxy. Внешний доступ настраивается через HTTPS серверным прокси пользователя. При отсутствии прокси первый запуск доступен локально; в README указывается, как подключить HTTPS до доступа из интернета.

В SQLite включены внешние ключи, WAL и ограниченное ожидание блокировки. Сетевые запросы к OpenAI выполняются вне транзакций базы. Нельзя запускать несколько экземпляров приложения на одной SQLite-базе в этой конфигурации.

Источник по развёртыванию: [FastAPI in Containers](https://fastapi.tiangolo.com/deployment/docker/). Сохранение volume независимо от жизненного цикла контейнера описано в [Docker Volumes](https://docs.docker.com/engine/storage/volumes/).

## Основные экраны

1. **Вход.** Логин, пароль, понятное сообщение об ошибке, выход из аккаунта.
2. **Предметы.** Список предметов, создание и переименование.
3. **Темы предмета.** Список тем, число готовых карточек, создание и переименование.
4. **Тема.** Документы с состоянием обработки; загрузка дополнительных файлов; список карточек и проверка предложенных вопросов.
5. **Создание карточек.** Выбор одной или нескольких тем, формата и количества вопросов; состояние генерации; выбор карточек для сохранения.
6. **Занятие.** Карточка с вопросом либо тест; ответ, самооценка, «Объясни проще», уточняющий вопрос и переход дальше.
7. **История.** Личные занятия, результат и продолжение незавершённого занятия.

Начальный интерфейс на русском. Он работает на телефоне и компьютере; кнопки имеют удобные для касания размеры, длинный текст переносится, загрузка с телефона позволяет выбрать фотографии. Распознавание камеры в реальном времени и нативные мобильные приложения не входят в первую версию.

## Вход и границы доступа

Пароли хранятся в виде Argon2-хешей. Аккаунты создаются и пароли сбрасываются CLI-командой внутри контейнера; пароль вводится скрыто. В репозитории и Docker-образе отсутствуют предустановленные учётные данные.

После входа сервер создаёт случайный сессионный токен, хранит его хеш и передаёт токен в HttpOnly-cookie с SameSite=Lax. В рабочем HTTPS-режиме cookie имеет Secure. Выход отзывает сессию; срок действия составляет 30 дней и проверяется сервером. Небольшое ограничение попыток входа защищает форму от перебора; неверный логин и пароль дают одинаковую ошибку.

API библиотеки, загрузка и скачивание документов, задачи генерации, карточки и объяснения доступны только после входа. Личные занятия и попытки всегда проверяются по владельцу. Изменяющие запросы требуют CSRF-токен и проверку разрешённого origin. Открытая междоменная политика CORS не включается.

Серверный ключ OpenAI задаётся через окружение контейнера. Он не возвращается браузеру, не попадает в логи и исходный код. Дополнение к ChatGPT и использование его подписки не требуются.

## Данные

| Объект | Связи и содержание |
| --- | --- |
| users | Логин, имя, хеш пароля, активность |
| Сессия входа | Пользователь, хеш токена, CSRF-секрет, срок действия |
| Предмет | Название, дата создания |
| Тема | Предмет, название, версия набора материалов |
| Документ | Тема, исходное имя, безопасное имя на диске, MIME, размер, SHA-256, статус |
| Страница источника | Документ, номер страницы, распознанный текст, статус обработки и предупреждения |
| Задача | Тип, инициатор, параметры и фиксированный набор источников, статус, ошибка, даты |
| Карточка | Одна тема, вопрос, ответ, формат, варианты ответа, версия, статус черновика или сохранённой карточки |
| Источник карточки | Карточка, документ, страница |
| Занятие | Пользователь, явно выбранные темы, формат, позиция, статус, даты |
| Карточка занятия | Занятие, позиция, снимок версии карточки и источников |
| Попытка | Пользователь, карточка занятия, ответ или самооценка, результат, ключ повторного запроса |
| Объяснение | Пользователь, карточка занятия, запрос, ответ, источники, связь с предыдущим уточнением |

Имена основных таблиц: users, subjects, topics, cards и documents. topics.subject_id ссылается на subjects.id; cards.topic_id и documents.topic_id — на topics.id. Вход, личные занятия, попытки и объяснения ссылаются на users.id. Названия и связи остальных таблиц уточняются в плане реализации.

Карточка всегда принадлежит конкретной теме. Занятие может объединять карточки из нескольких явно выбранных тем; такая выборка не создаёт новый предмет и не переносит карточки.

Библиотека сохраняет оригиналы файлов и распознанное содержание. Снимок карточки занятия сохраняет старые формулировки даже после исправления карточки в библиотеке. В первой версии пользователь не удаляет источники: изменение названий и добавление материалов сохраняют историю. Физическое удаление и управление архивом можно добавить позднее.

## Загрузка и распознавание

PDF, JPEG, PNG и WebP загружаются в конкретную тему. Сервер проверяет фактический формат, размер и читаемость файла; имя пользователя не используется как путь. Оригинал сохраняется на volume до распознавания. Лимит первой версии — 20 МБ на файл и 50 страниц на PDF. Интерфейс показывает ограничения до загрузки.

Тот же файл в той же теме определяется по SHA-256 и не создаёт дубликат. Повторная загрузка в другую тему допустима. При ошибке распознавания оригинал остаётся доступным и задачу можно запустить повторно.

Для текстовых PDF сначала извлекается текст локально по страницам. Страницы с изображениями, схемами или без читаемого текста обрабатываются через vision модели Luna; наличие текста само по себе не исключает обработку визуального содержимого. Фотографии также обрабатываются через vision. Вызовы для PDF могут передавать `input_file`; изображения передаются как `input_image`. Обработка идёт небольшими группами страниц с известными номерами; модель возвращает структурированный текст и предупреждения. Пустые страницы и неуверенно распознанные фрагменты отмечаются явно.

Результат сохраняется по страницам. Готовые страницы используются повторно без нового распознавания. Генерация карточек доступна после готовности документа. При частичной ошибке интерфейс сообщает, что обработка не завершена, и предлагает повторить ошибочную часть.

Внешние URL для импорта файлов не поддерживаются в первой версии: пользователь загружает сами файлы.

OpenAI документирует [PDF inputs](https://developers.openai.com/api/docs/guides/file-inputs) и [image inputs](https://developers.openai.com/api/docs/guides/images-vision). У [GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna) заявлены image input и structured outputs. Наличие этих возможностей не заменяет проверку распознавания на конкретном учебнике.

## Фоновые задачи

Обработка файлов, создание карточек и объяснения сохраняются как задачи в SQLite. В процессе FastAPI работает один фоновый исполнитель; отдельные Redis и Celery не требуются. Браузер получает идентификатор задачи и периодически проверяет статус, поэтому закрытие вкладки не отменяет операцию.

Состояния задачи: queued, running, succeeded и failed. При перезапуске queued продолжаются, а оставшиеся running переводятся в failed с сообщением о прерывании и возможностью явного повтора. Автоматическое повторение потенциально оплачиваемого вызова после неопределённого сетевого результата не выполняется. Уже сохранённые результаты не дублируются.

Неудачный ответ модели, отказ, тайм-аут или неполный JSON не записывается как успешный набор карточек. Генерация ограничивает число запросов и длину ответа; интерфейс позволяет повторить операцию.

## Генерация и выбор карточек

Запрос обязательно содержит непустой список тем, формат и число вопросов от 1 до 30. Можно дополнительно выбрать документы внутри этих тем; по умолчанию используются все готовые документы выбранных тем. Документы из других тем отклоняются сервером. Сервер фиксирует состав источников на начало задачи. При неготовых документах пользователь явно выбирает дождаться обработки либо продолжить с готовыми.

Материалы одной темы передаются отдельно от других. При выборе нескольких тем нужное число вопросов распределяется по темам; число вопросов должно быть не меньше числа тем, чтобы каждая могла получить хотя бы один вопрос. Вопросов, требующих смешения разных тем, в первой версии нет. Приложение не использует темы за пределами выбранного списка и не подставляет внешние сведения вместо отсутствующего учебного текста.

Для одного запуска действует ограничение 100 000 символов извлечённого текста. Превышение даёт понятное сообщение и предложение выбрать меньше документов; скрытого обрезания источников не происходит. Векторная база и автоматический поиск по большой библиотеке пока не нужны.

Ответы модели используют OpenAI Structured Outputs, а не только просьбу вернуть JSON в промпте. Структуры описываются Pydantic-моделями; Python SDK вызывает Responses API через `responses.parse` с `text_format`, либо передаёт эквивалентную JSON Schema с `strict: true`. Для каждого объекта схема запрещает дополнительные свойства. Все поля, которые требуются API, обязательны; отсутствие применимого значения явно представляется null или пустым списком согласно типу поля.

Для распознавания задаётся типизированный результат страниц и предупреждений; для генерации — результат с карточками, источниками и сообщением о нехватке материала; для объяснения — текст, пример и ссылки на источники. Типы сохраняются в коде, а JSON Schema выводится из них. Отказ модели и незавершённый ответ проверяются отдельно от успешного типизированного результата. В базу записываются только полностью разобранные и проверенные результаты.

Luna возвращает вопросы по строгой JSON-схеме: тема, вопрос, ответ, формат, варианты ответа и ссылки на страницы источников. Сервер дополнительно проверяет допустимые идентификаторы источников, номера страниц и единственный правильный вариант теста. Соответствие JSON-схеме проверяет форму ответа, а соответствие учебным фактам проверяется отдельно. Генерация инструкциями ограничивается учебными фактами; загруженные документы не могут изменить правила доступа и выбора тем.

Официальная документация: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

Результат открывается как черновики. Пользователь выбирает карточки для сохранения, может поправить вопрос и ответ, затем начать занятие. При нехватке материала приложение возвращает меньше вопросов и сообщает причину.

Новый документ увеличивает версию материалов темы. Старые карточки и занятия остаются доступными, а новый запуск генерации использует обновлённый состав документов. Добавление файла не запускает платную генерацию автоматически.

## Занятие и объяснения

При старте фиксируется выбранный набор сохранённых карточек и их версий. Карточки перемешиваются один раз, порядок сохраняется.

Во флеш-карте сначала виден вопрос. «Показать ответ» открывает ответ; затем «Помню» или «Повторить» фиксирует самооценку. В тесте сервер проверяет выбранный вариант; правильный ответ не выдаётся до фиксации попытки. Переворот готовой карточки и переход дальше не вызывают OpenAI API.

Ответ сохраняется перед переходом дальше. Повторный запрос с тем же идентификатором не создаёт новую попытку. Новая вкладка или другое устройство продолжает занятие с сохранённой позиции; при конфликте интерфейс обновляет актуальное состояние.

«Объясни проще» создаёт объяснение текущей карточки с короткими предложениями и знакомым примером. Оно использует сохранённые источники карточки из её темы. Аналогия явно отмечается как пример. Можно задать уточняющий вопрос, прочитать ответ и вернуться к той же карточке. Объяснения и уточнения сохраняются в личной истории; обращение за объяснением само по себе не считается правильным ответом.

История показывает даты, темы, результаты и незавершённые занятия. Повторение ошибок создаёт новое занятие с карточками, отмеченными «Повторить» либо отвеченными неверно; исходное занятие остаётся доступным.

## Конфигурация и эксплуатация

В `.env.example` документируются OPENAI_API_KEY, OPENAI_MODEL, APP_ORIGIN, COOKIE_SECURE, порт и путь DATA_DIR. Настоящий `.env`, документы и SQLite исключаются из Git и Docker build context.

Запуск: заполнить настройки, выполнить `docker compose up -d --build`, затем создать аккаунты через CLI. Compose задаёт restart policy и проверку работоспособности. Конечный контейнер работает без root; приложение не создаёт демонстрационных аккаунтов в рабочем режиме.

Перед обновлением выполняется резервная копия. Для согласованного сохранения SQLite и файлов первая версия использует короткую остановку приложения, копирование всего volume, затем запуск. README содержит команды восстановления в отдельный volume. Команды обычного обновления не удаляют volume. Успешное восстановление проверяется при подготовке релиза.

Развёртывание на сервере пользователя и реальный запрос OpenAI потребуют его окружения и API-ключа. Локальная проверка без ключа использует явно тестовый адаптер модели; рабочее приложение при отсутствующем ключе показывает, что AI-функции не настроены.

## Проверки и критерии готовности

- Вход, выход, неверный пароль, закрытая регистрация, срок сессии, CSRF и отсутствие доступа к документам без входа.
- Два аккаунта видят общие предметы и темы, но не получают чужие занятия и объяснения.
- Создание предмета, двух тем, загрузка PDF и фото, добавление ещё одного документа в существующую тему.
- Сохранение оригиналов, карточек и личной истории после перезапуска приложения и пересоздания Docker-контейнера с прежним volume.
- Генерация по одной теме, по двум выбранным темам и отказ при пустом выборе; источники другой темы не передаются модели.
- Проверка и сохранение выбранных черновиков, занятие только с выбранными карточками.
- Сохранение попыток без дубликатов, продолжение занятия с другого устройства, история и повторение ошибок.
- Простое объяснение, уточняющий вопрос и сохранение обоих результатов.
- Добавление файла во время занятия сохраняет его набор карточек и историю.
- Проверяется наличие строгой JSON Schema в реальном запросе к API; типизированный ответ проходит Pydantic и проверку допустимых источников. Отказ модели, незавершённый ответ, невалидная схема, недоступный API, повреждённый файл, превышение лимитов и прерванная задача дают понятные состояния и не создают частично сохранённых карточек.
- Адаптивный интерфейс проверяется на ширинах 360, 390 и 1280 пикселей; формы, карточки и диалоги доступны с клавиатуры.
- Сборка React, тесты FastAPI, Docker Compose и восстановление резервной копии проверяются до передачи.
- При наличии ключа проводится отдельная проба Luna на небольшом реальном PDF и фотографии: качество распознавания, соответствие карточек источникам и простое объяснение.
