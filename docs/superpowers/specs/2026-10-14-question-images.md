# Изображения вопроса и ответа — проект отдельного этапа

## Назначение и границы

После пяти типов заданий и регенерации текста добавить по одной необязательной
картинке к вопросу и к ответу. Два способа: загрузить собственную картинку либо
явно сгенерировать одну через OpenAI. Ничего не генерируется при открытии
страницы, создании текстовых вопросов, начале занятия или регенерации текста.
Аудио не добавляется. Нет нового внешнего хранилища или отдельного сервиса.

Это дополнение к спецификации `2026-10-14-language-exercises.md`.
Картинки не меняют источник правильного ответа и правила оценивания.
Ручные картинки могут иллюстрировать задание; автоматическое OCR/извлечение
новых фактов из них и новый тип «визуальная проверка моделью» вне первой версии.
Пользователь подтвердил: пока только иллюстрации, не самостоятельный материал
«Что изображено?». Формулировка и правильный ответ должны определяться текстом
и учебными источниками без картинки. Интерфейс поясняет это при добавлении.
Новые asset-source refs/vision-входы не добавляются; regenerate/explain не
получают прикреплённые иллюстрации. Семантическую совместимость картинки с
текстом проверяет пользователь, сервер проверяет версию/тип и доступ.

## Последующее описание картинки: отдельная роль источника

Решение «только иллюстрации» сохраняется для этого этапа и всех прежних типов.
Пользователь затем отдельно подтвердил `2026-10-14-free-responses.md`: новый
picture_description вводит image_role=source на CardImage/SessionImage и
передаёт выбранную картинку модели для подготовки/проверки/регенерации.
Эта ветка не распространяется на обычные иллюстрации. Смена source asset
инвалидирует критерии и требует новой подготовки; старое занятие/повтор
сохраняют свой source asset и критерии. Cleanup расширяется на активные vision
Job refs, остальные правила последней ссылки/owner/private файлов сохраняются.
0008 журнал image requests допускается установить с отключённой платной
генерацией перед 0009 свободных ответов; включение Images API не требуется.
План дополнения: `../plans/2026-10-14-free-responses.md`.

## Работа в интерфейсе

На экране редактирования/проверки вопроса два блока: «Картинка вопроса» и
«Картинка ответа». Для каждого: загрузить, необязательная «Сгенерировать
(платно)», предпросмотр, подпись для доступности, заменить/убрать.
Загрузка/генерация создаёт кандидата. Вместе с сохранением редактора кандидат
прикрепляется атомарно; отказ от кандидата не удаляет текущее изображение.
Незавершённые кандидаты доступны при возвращении к этому вопросу и удаляются
явным отказом или удалением самого вопроса, не превращаются в неучтённые файлы.

При регенерации текста текущие изображения не меняются автоматически.
В сравнении старого/нового вопроса видны текущие картинки и явный выбор
«Оставить»/«Убрать» для нового варианта. Пользователь проверяет, что иллюстрация
подходит новому тексту. Новая картинка запрашивается отдельным действием.

В занятии question image видна с вопросом. Answer image, её ID и alt не
попадают в публичный ответ до проверки quiz или раскрытия flashcard.
Скрытая картинка не предзагружается браузером. После проверки и в истории
показываются соответствующие изображения из снимка, а не текущая версия Card.

Нельзя считать AI-иллюстрацию достоверной фотографией события или источником
исторических фактов. Она отмечается «Создано ИИ», родитель проверяет её перед
сохранением. По умолчанию изображения генерируются без текста; если добавляют
текст в prompt, его язык соответствует языку задания. Перевода содержимого нет.

## Форматы и приватное хранение

Первая версия: JPEG, PNG и WebP, до 10 MiB, до 20 мегапикселей при декодировании.
SVG, анимация и другие форматы не принимаются; ошибка объясняет допустимые
форматы. Проверять реальные байты изображения, а не только расширение/MIME.
Нормализовать ориентацию, удалить EXIF/метаданные, уменьшить длинную сторону
до 2048 пикселей, сохранить безопасный статичный WebP. Alpha сохраняется.
Подпись alt до 500 символов; без обязательного отдельного AI-запроса на её создание.

Файлы в `/data/question-images`, случайные имена и относительные внутренние
пути. Не монтировать каталог как публичный static. `.env` и загруженные картинки
не входят в Git/Docker build context. Ответы изображения: корректный Content-Type,
`X-Content-Type-Options: nosniff`, `Cache-Control: no-store`.

ImageAsset хранит ID, путь, хеш, размер/геометрию, origin upload/generated,
owner_user_id, stage draft/ready, целевой card_id/version/slot для кандидата,
метаданные провайдера без секретов. CardImage связывает Card, asset и slot
question/answer, имеет уникальность card_id+slot. SessionImage связывает
SessionCard, asset, slot и фиксированную alt; индекс по asset_id.
JobImage фиксирует связь кандидата генерации с Job. Файлы неизменяемые.
Repeat копирует SessionImage из исходного занятия вместе с новыми SessionCard
в одной транзакции, не перечитывает CardImage; URL принадлежит новому занятию.
Старые занятия без картинок получают пустой набор связей.

Кандидаты имеют полный цикл writing→draft→ready, draft→obsolete при конфликте
версии, draft/obsolete→discarded и затем deleting/deleted после последней ссылки.
Own list/preview показывает draft и obsolete после возвращения. Obsolete можно
явно перепривязать к текущей версии после проверки картинки, без нового вызова
модели; для удалённой Card это невозможно. Discard очищает все Job/draft refs.
Preview — same-origin endpoint с проверкой владельца, не blob URL; CSP сохраняется.
Промежуточные файлы учитываются состоянием writing и очищаются после сбоя.

Доступ библиотеки требует входа и существующего вопроса/кандидата с разрешением.
Доступ из истории требует владения занятием и связи SessionImage. Answer slot
доступен только если вопрос раскрыт либо сохранена Attempt; URL библиотеки
по-прежнему доступен вошедшим пользователям общей библиотеки. Режим экзамена
и роли parent/child не добавляются. Пути файлов и секреты не выдаются клиенту.

Изменение изображения увеличивает Card.version. SessionImage сохраняет старый
asset при замене/удалении изображения Card. Удаление Card/Topic/Subject убирает
текущие связи и кандидаты/задачи; история сохраняется. Bulk-delete истории
убирает SessionImage. Файл удаляется только после последней ссылки CardImage,
SessionImage, JobImage или действительного редактируемого кандидата.
Удаление последней ссылки повторяемо, очистка не касается документов/чужих файлов.
Ошибка записи или отменённый поздний worker не оставляют бесхозные файлы.
Cleanup под write-lock проверяет ссылки и помечает asset deleting до unlink;
attach не использует deleting/discarded. Ошибка unlink сохраняет deleting
для повторной очистки. Файловая операция и SQLite не объявляются общей атомарной
транзакцией: тестируется восстановление каждого промежуточного состояния.

В image-этапе apply-regeneration принимает image_updates по тому же контракту,
что CardEdit. Новый текст, keep/remove/replace, увеличение version и метка
применения сохраняются одной SQLite-транзакцией. Fingerprint применения включает
image_updates. Отдельный PATCH картинки после применения текста не используется.

## Генерация и контроль расходов

Использовать существующий OpenAI account/API key, отдельный адаптер Images API.
Настройка `IMAGE_GENERATION_ENABLED=false` по умолчанию. `OPENAI_IMAGE_MODEL`
задаётся оператором; пустой model не включает платные вызовы. Не менять модель
текстовых вопросов. Config/model валидируются без пробной генерации.
Фактический доступ проверяется только первым явным платным запросом пользователя.

Одна пользовательская попытка — один запрос и одно изображение (`n=1`, фиксированные
`size=1024x1024`, `quality=low`, `output_format=webp` для совместимого model).
Перед кнопкой видны платность и параметры. Точная стоимость не обещается:
зависит от model, размера/качества и входа. Оценка берётся из актуальной
документации/калькулятора при выборе model, а не из неподтверждённых 4–5 центов.
Сохраняются доступные usage/model параметры, но отсутствие usage не превращается
в утверждение «бесплатно». Никаких массовых генераций или automatic quality=auto.

Для управления расходами: идемпотентность нажатия, один активный Job на card/slot,
настраиваемый оператором дневной лимит попыток провайдера (проектный default 10).
ImageRequest(job_id, attempt_no, request_key, reserved_at, status) резервирует
слот атомарно непосредственно перед отправкой; reserved/sent/succeeded/failed/
unknown учитываются, включая ручной retry того же Job. Отмена/перезапуск не
возвращают слот. Для повторов используется отдельный image endpoint с явной
платностью; общий /jobs/{id}/retry отвергает generate_image.
IMAGE_BUDGET_TIMEZONE задаётся оператором, default Europe/Vilnius; интерфейс
показывает время следующего сброса. В БД временные метки UTC, границы суток
считаются через ZoneInfo с учётом DST. Это общий лимит семьи, не только успехов.
Это ограничение числа запросов, не гарантия долларового лимита OpenAI.

SDK retries выключены для image generation. Не переносить автоматически три
попытки текстовой модели на создание картинок: при timeout результат/списание
может быть неизвестным. Показывать такой исход и предложить отдельное ручное
повторение с предупреждением о возможной дополнительной оплате. Если приложение
получило данные и не успело сохранить, сначала повторяется локальное сохранение,
а не создание картинки. Проверенные сохранённые картинки используются повторно.
Отключение/отсутствие доступа/отказ API не влияет на текстовые задания и upload.

Кандидат не прикрепляется к вопросу, если его версия/тип изменилась или вопрос
удалён. Пользователь видит конфликт; поздний worker не воскрешает вопрос.
После отказа кандидата задача очищает исходные фрагменты и локальный файл,
если не осталось законных ссылок.

## Приёмка

Upload/generation→preview→save→study→answer/reveal→history на desktop/mobile.
Проверить неавторизованный доступ, чужую историю, прямой URL скрытой answer image,
отсутствие ID/alt/предзагрузки до раскрытия, корректную картинку старой версии
после замены. MIME-подмена, повреждение, SVG, слишком большой файл/геометрия,
ориентация/EXIF, прозрачность. Проверить все виды удаления, последнюю ссылку,
отменённый worker, завершение после удаления и восстановление из резервной копии.
AI-тесты с подменой провайдера: один клик/один Job/один запрос, лимит, отказ,
timeout без автоматического повторения, конфликт версии, оригинал сохраняется.
Реальные оплачиваемые тесты не нужны для обычного CI.

Источники API-параметров и стоимости (проверены 14 октября 2026):
[Images API guide](https://developers.openai.com/api/docs/guides/image-generation#customize-image-output),
[OpenAI pricing](https://developers.openai.com/api/docs/pricing).
Выбор image model и оценка расходов уточняются при реализации этого отдельного
этапа, до включения генерации в `.env`. Пока подготовлены только документы.
