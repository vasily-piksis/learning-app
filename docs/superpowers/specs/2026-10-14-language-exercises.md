# Пять типов языковых заданий — проект спецификации

## Подтверждённый объём

Добавить письменный ответ, пропуски, окончания, сопоставление пар и сборку
предложения. Пропуски и окончания — отдельные типы. Озвучка, диктант, запись
голоса и новые платные API не входят в эту работу. Документ описывает решения
для проверки перед реализацией; код приложения и сервер сейчас не меняются.

FastAPI, SQLite, React/shadcn и Docker сохраняются. Модель создаёт черновики
через существующий Structured Outputs и существующую политику трёх попыток.
Проверка ответа выполняется на сервере без вызова модели. Объяснение ответа
остаётся существующим отдельным действием с обращением к модели.

## Последующие свободные ответы: граница совместимости

Пользователь 14 октября отдельно подтвердил расширение в
`2026-10-14-free-responses.md`: свободный письменный ответ/счётчик, затем
описание картинки, затем голосовой ввод. Ограничения «без модели при проверке»
и «без аудио» выше относятся к этому первому этапу, не ко всему будущему приложению.
written остаётся коротким детерминированным ответом; label в следующем этапе
уточняется до «Короткий письменный ответ», free_response — «Свободный ответ».
Не расширять written до сочинения и не переключать старые Attempt на AI grading.
Новые типы остаются quiz; их async Evaluation и _grading v2 добавляются после
этого плана. Start не вызывает модель и тогда; default mixed использует общий
набор прежних шести типов, платные новые типы включаются только явно.
Текущие восемь методов/счётчики/whitelists расширяются по новому плану, без
перезаписи старых snapshots или добавления новых критериев в v1 результаты.
Реализация этих дополнений: `../plans/2026-10-14-free-responses.md`.

## Пользовательский сценарий

Путь: библиотека → предмет → тема. Вместо двух кнопок показываются селектор
«Способ проверки» и одна кнопка «Начать». В селекторе: «Флеш-карты»,
«Выбор ответа», «Письменный ответ», «Пропуски», «Окончания», «Пары»,
«Сборка предложения», «Смешанная практика». По умолчанию «Флеш-карты».
Режимы в API остаются flashcard/quiz; тип вопроса не создаёт отдельных наборов.

На отдельном экране «Создать вопросы» выбираются материалы, общее количество,
цель практики и один или несколько типов. По умолчанию цель «Содержание темы»
и существующий выбор ответа.
Новые типы не создаются автоматически при открытии старой темы. После генерации
родитель проверяет, редактирует и сохраняет черновики по существующему сценарию.
Добавление материалов или изменение способа не удаляет готовые вопросы.

Один выбранный тип запускает quiz только с сохранёнными вопросами этого типа.
«Смешанная практика» по умолчанию выбирает общий готовый набор типов всех
выбранных тем, показывает его явно и запускает quiz с этим набором; только для
этого варианта раскрывается необязательный список типов для включения/исключения.
Тип, готовый лишь в части тем, можно явно добавить с показом missing_pairs.
Если общего набора нет, необходимо выбрать типы и подготовить пробелы; темы
не исключаются автоматически и отсутствие выбора не означает «все типы».
У вариантов видны количества действительно готовых вопросов. Нулевой тип
можно выбрать: вместо «Начать» появляется «Подготовить задания». Подготовка
открывает отдельную форму с выбранной темой/способом, материалами и количеством.
Нажатие кнопки генерации — явный запрос модели. При готовности показывается
«Начать», запуск занятия никогда не обращается к модели.

Видны отдельные состояния: нет заданий, подготовка идёт, есть черновики для
проверки, есть готовые задания, подготовка не удалась, нужны материалы.
Готовые вопросы и дополнительная текущая подготовка могут существовать вместе:
например, «Готово 10; ещё 5 нужно проверить». Дублирующее нажатие открывает
уже существующую задачу вместо второго запроса. После проверки готовые задания
используются повторно; «Добавить задания» — отдельное явное действие.

Для нескольких тем показывается готовность каждой пары тема×выбранный тип.
Для одного метода нужен хотя бы один готовый вопрос этого метода в каждой
теме. Для mixed нужны все явно выбранные типы в каждой выбранной теме.
Если чего-то нет, интерфейс перечисляет пробелы и открывает подготовку только
для них. В первой версии подготовка идёт по одной теме за раз, без неявного
запуска пачки оплачиваемых задач. Пользователь может явно изменить темы/типы.
Молчаливое исключение темы/типа запрещено. Старые занятия открываются по URL.

Topic.practice_availability возвращает по flashcard и шести типам ready_count,
draft_count, needs_options_count (только choice), preparation_job_id/status
для задач, доступных текущему пользователю, и has_ready_materials. Готовность
choice требует сохранённых корректных вариантов; новых типов — сохранённого
валидного exercise. Счётчики не раскрывают решения. Start проверяет готовность
повторно в транзакции и при пробеле возвращает 422 с missing_pairs и действием
подготовки, не создавая Job. Лимит занятия остаётся 300.
Availability также возвращает last_outcome: method, source_fingerprint, reason
и stale. Непригодность описывается как результат по конкретным материалам,
не как постоянный запрет типа для темы; новые/изменённые материалы делают её stale.

## Применимость: цель пользователя и содержимое материалов

Название предмета не определяет форматы: история на польском может изучаться
как история либо как упражнение по польскому. Язык документа тоже не означает,
что пользователь хочет тренировать грамматику. Автоматическая классификация
по названию темы/предмета и отдельный платный запрос модели не используются.

При создании пользователь выбирает «Что тренируем?»:

| Цель | Доступные типы создания | Примеры |
| --- | --- | --- |
| Содержание темы (по умолчанию) | choice, written, gap, matching | дата события, пропущенное имя, человек → событие |
| Язык и грамматику | все шесть типов | буквы, окончания, слово → определение на том же языке, сборка предложения |

Это выбор цели текущей генерации, а не новое обязательное свойство предмета.
Старые темы не требуют перенастройки. На форме видно пояснение, почему окончания
и сборка предложения доступны для языковой практики. Смена цели не отправляет
запрос модели; несовместимые галочки снимаются с явным сообщением.

Среди доступных типов пользователь выбирает нужные. В той же генерации модель
проверяет, достаточно ли источников для каждого выбранного типа. Если для
окончаний нет грамматического контекста/примеров или для пар нет двух однозначных
соответствий, она возвращает unsupported_types с причиной и создаёт только
обоснованные задания, не подменяя их другим типом. Причины видны в результате;
при отсутствии любых заданий — явный пустой результат с переходом к материалам.
Структура и ссылки проверяются сервером, содержательная точность — также при
проверке черновиков родителем. Решение модели не объявляется гарантированным.

При запуске доступность определяется уже сохранёнными вопросами, а не новой
догадкой модели и не прошлой целью генерации. Если пользователь осознанно
сохранил языковое упражнение в теме истории, оно доступно как языковой тип.

«Флеш-карты» использует те же вопросы, показывает задание и после раскрытия
полное решение. Новый тип не превращается автоматически в тест с вариантами.
Для пустой темы можно явно подготовить флеш-карты из материалов (choice,
mode=flashcard); новые специализированные типы требуют mode=quiz. Существующие
вопросы с полным решением пригодны как флеш-карты без генерации дублей.
Для старых флеш-карт без вариантов есть явная «Подготовить варианты»:
prepare_quiz вызывается отдельным действием, не из start. Его результат —
кандидаты вариантов в Job.result; исходные Card не меняются до принятия.
Принятие выбранных кандидатов проверяет версии Card и источники атомарно.
После него choice становится готовым. UI не начинает занятие автоматически.

## Типы, данные и проверка

Вопрос получает `question_type`: `choice`, `written`, `gap`, `ending`, `matching`
или `ordering`. Старые вопросы получают `choice`; это не меняет их содержание.
`mode` остаётся `quiz | flashcard` для совместимости с нынешними API и историей.
В `cards` добавляется `exercise` — типизированное содержимое в JSON, null для
`choice`. У новых типов exercise — единственный источник решения; `answer`
формируется из него сервером, не редактируется независимо. Флеш-карта, история
и explain используют это же решение. Для choice старый контракт сохраняется.

- **written:** `accepted_answers` (1–10 непустых строк, каждая до 1000 символов),
  `case_sensitive` (по умолчанию false). Одно поле ввода и несколько явно
  заданных допустимых ответов; свободные эссе и семантическая оценка не входят.
- **gap:** `segments` (до 30 элементов `{text}` или `{gap_id}`), `gaps`
  (1–6 элементов `{id, accepted_answers}`, варианты до 200 символов),
  `case_sensitive`, `accepted_combinations` (1–20 полных сочетаний значений
  в порядке gaps). Каждый gap встречается ровно один раз; заполняется буква,
  слово или короткая фраза. Сочетания содержат ровно все gaps; каждый их элемент
  принадлежит accepted_answers своего поля. Итог верен только при совпадении
  полного сочетания. accepted_answers каждого поля в точности совпадает с
  проекцией допустимых комбинаций после нормализации; «мёртвые» значения и
  дублированные сочетания запрещены. Для неверного ответа parts строится относительно ближайшего
  допустимого сочетания по числу несовпадающих полей; при равенстве — первого
  в сохранённом списке. Если значения по отдельности допустимы, но сочетание
  нет, добавляется сообщение «Эти формы не подходят друг к другу».
- **ending:** `segments` и `gaps` того же формата, но ровно один пропуск.
  Задание явно задаёт контекст и требуемую грамматическую форму; основа слова
  видна, вводится только окончание. В первой версии окончание непустое:
  упражнения на нулевое окончание или изменение основы не генерируются.
  accepted_combinations устроен как gap, с одним полем. Отдельная подпись типа,
  инструкция и редактор предотвращают смешение с общим пропуском.
- **matching:** `pairs` (2–8 `{left, right}`), подписи до 200 символов.
  Тексты внутри каждой колонки различаются после нормализации; неоднозначные
  пары не сохраняются. При запуске обе колонки получают независимые случайные
  идентификаторы и независимо перемешиваются. Полное соответствие хранится
  только в закрытом снимке занятия. Ответ — полная биекция между колонками;
  общий успех — только при верных парах, обратная связь также по каждой паре.
- **ordering:** `tokens` (2–20 строк до 100 символов), `accepted_orders`
  (1–5 допустимых последовательностей строк). Каждая последовательность
  содержит то же мультимножество токенов. Пунктуация входит в токены; это
  явно видно в задании. При запуске токены получают случайные идентификаторы
  и перемешиваются; верные последовательности скрыты. Повторяющиеся одинаковые
  слова разрешены: проверяется последовательность текстов, а не исходных ID.

Текст нормализуется через Unicode NFC, удаление пробелов по краям и сведение
внутренних последовательностей пробельных символов к одному пробелу.
Если `case_sensitive=false`, применяется Unicode casefold с повторной NFC.
Диакритика, окончания и пунктуация сохраняются; нечёткое сравнение и
автоматическая транслитерация не применяются. Дубликаты допустимых ответов
после нормализации запрещены. Язык материала, вопроса и ответов сохраняется.
Перевод учебного содержимого исключён, даже по явно указанному target_language;
переключается только язык интерфейса. Не создаются задания en→pl/lt→ru.
Языковые упражнения используют слова, формы и контекст исходных материалов.
Если источников недостаточно, возвращается причина. Для источников на разных
языках отдельный вопрос ссылается на фрагменты одного языка; не переводит их
на язык интерфейса и не соединяет разноязычные ответы.

Форма перевода убирается из генерации. Новый API отвергает непустой
target_language с 422. Уже созданные переведённые вопросы/история сохраняются.
Незавершённая старая генерация или её retry с target_language не выполняют
перевод: задача получает понятную ошибку и предложение создать новую на
исходном языке; сохранённые результаты не удаляются.

## Генерация и редактирование

В `GenerateBody` добавляется `question_types` (1–6 уникальных значений,
по умолчанию `["choice"]`) и `practice_goal: content | language`
(по умолчанию content). ending/ordering при content отклоняются с 422 и
подсказкой выбрать языковую практику. `count` остаётся общим числом вопросов (1–30),
а не количеством на каждый тип. Для нескольких тем нужно
`count >= число тем × число типов`, иначе 422 с понятным сообщением.
Квоты распределяются равномерно между темами и типами; одна генерация на тему
получает все её квоты. Неполный результат допустим с явной причиной, неподходящий
материал не превращается в выдуманное грамматическое упражнение.
`Generated.unsupported_types` — список `{question_type, reason}` только
из запрошенных типов; причина непустая. Тип не может одновременно присутствовать
в unsupported_types и сгенерированных вопросах. Для неполной квоты поддерживаемого
типа остаётся insufficient_reason. Старые задачи без новых полей получают
content/choice; отсутствие unsupported_types в старом сохранённом результате
считается пустым списком.

Новая UI всегда отправляет idempotency_key на /generate и prepare-options,
сохраняет его при повторе HTTP. Сервер атомарно связывает key с Job и fingerprint
тела/снимков источников. Тот же key/payload возвращает прежнюю задачу даже после
завершения; другой payload с тем же key — 409. Активные одинаковые scope
переиспользуются без второй генерации. Legacy запрос без key имеет защиту
активного fingerprint, но не обещает terminal replay. Один прежний непригодный
результат не блокирует осознанный повтор с новым key и видимой причиной.

Новые схемы результата узкие, с `extra=forbid`, проверкой вида exercise,
границ, квот, языка, topic_id и источников. Сохраняется проверка настоящих
document_id/page. Модель не выбирает произвольный тип вне запроса. Ключ
дубликата учитывает тему, язык, тип, вопрос, ответ и содержимое exercise:
разные типы могут отрабатывать одно слово, одинаковое упражнение не дублируется.

Тип показывается в списке вопросов, черновиках и подробном просмотре.
Редактор меняет параметры текущего типа, полное решение и допустимые ответы.
Для новых типов полное решение вычисляется после правки параметров; нельзя
сохранить независимое противоречащее answer. Письменное задание явно просит
слово/дату/короткий ответ с контекстом. Ordering перечисляет допустимые порядки
или явно требует восстановить конкретное предложение из материала; не обещает
оценку любого грамматически правильного предложения.
Изменение типа существующего вопроса в первой версии не входит в объём.
Проверка `version` и ошибка 409 при конфликте сохраняются.

## Регенерация одного вопроса

В черновиках и экране вопросов темы рядом с ручным редактированием есть
«Регенерировать». Это явный оплачиваемый запрос существующей текстовой модели
на один вопрос того же типа, темы и языка из его доступных источников.
Перегенерируются вопрос, критерии/варианты ответов и структура exercise вместе.
Никакие другие вопросы темы не изменяются. Если материалов нет или контекст
недостаточен, исходный вопрос остаётся и показывается причина.

Результат — кандидат в Job.result, не новая Card и не автоматическая замена.
Показываются прежний и новый вариант. Пользователь может поправить кандидата,
«Применить» либо «Оставить прежний». Применение проверяет captured base_version,
статус Card/темы/источников, тип, язык и отсутствие дубликата другого вопроса.
Обновление Card атомарно, version увеличивается, draft/saved статус сохраняется.
Card.job_id остаётся происхождением создания, новая задача хранит applied_version.
Конфликт 409 не перезаписывает более свежие правки.
Apply сохраняет applied_fingerprint/applied_result: одинаковое тело возвращает
сохранённый результат, изменённый кандидат — 409; более поздняя правка Card не
выдаётся как результат прежней операции. Apply/Discard взаимоисключающие
переходы под транзакцией; отказ не откатывает уже применённую правку.

Повтор клика при уже queued/running регенерации того же card_id/base_version
открывает текущую задачу. Новый UI передаёт idempotency_key; завершённый,
но не принятый кандидат показывается до нового запроса. «Другой вариант»
явно создаёт новый key; приватные Jobs другого пользователя не раскрываются.
Прогресс и кандидат сохраняются после закрытия страницы.
Отказ очищает кандидат и его исходные фрагменты. Удаление вопроса/темы/предмета
отменяет связанную задачу, очищает payload/result; поздний worker не восстанавливает
вопрос. История и активные занятия сохраняют старые снимки.

## Изображения: отдельный последующий этап

Пользователь добавил ручную загрузку картинки к вопросу/ответу и необязательную
генерацию одной картинки по явной кнопке. Это отдельный этап после текстовых

Изображения не создаются автоматически при подготовке/регенерации текста.
Картинка ответа скрыта в занятии до проверки/раскрытия, файлы приватны и
учитываются в очистке, снимках истории и резервных копиях. Аудио по-прежнему нет.

## Занятие, результаты и приватность

На сервере выделяются отдельные операции построения снимка, публичного
представления и проверки. Публичное представление собирается по разрешённым
полям: до ответа не выдаются `answer`, accepted_answers, accepted_orders,
правильные пары и индексы вариантов, в том числе в HTTP-ошибках.
Для пар и порядка случайные ID не кодируют правильный порядок или соответствие;
перемешивание сохраняется в снимке и не меняется после перезагрузки страницы.
Новое/повторное занятие получает новые ID и перестановку из неизменного
содержимого старого снимка; модель не вызывается. Проверяется, что банк ordering
не выдан уже готовым допустимым порядком; бессодержательные задания, где нельзя
получить неправильный порядок различимых слов, не генерируются.

В `AnswerBody` сохраняются старые поля; добавляются `text`, `gap_answers`,
`pairs` и `order`. Передаётся только поле соответствующего типа. Сервер
проверяет полноту, ID, размеры и отсутствие чужих/повторных элементов.
Повтор запроса с тем же idempotency_key и тем же ответом возвращает тот же
результат, изменённый ответ — 409. Порядок ключей gap_answers и пар не влияет
на идентичность ответа; порядок токенов влияет.

Снимок занятия фиксирует тип, правила и полное решение. Изменение/удаление
вопроса либо материала не меняет старую историю. История сохраняет введённый
ответ, показывает полное решение, ошибки по полям/парам и позволяет повторить
ошибочные задания без генерации. Старые JSON-снимки без новых полей читаются
как `choice`, включая снимки старых флеш-карт.
Обратная связь записывается в момент ответа в Attempt.value._grading
({version:1, correct, parts, message_code}). История и идемпотентный повтор
читают сохранённые correct/parts, не пересчитывают их новым grader. При сравнении
идемпотентности _grading исключается из пользовательской части. Старые Attempt
без метаданных используют сохранённый correct и старый ответ, без нового grader.
Набранный, но не отправленный ответ в первой версии не сохраняется между
перезагрузками. В истории показан способ проверки и результаты по заданиям;
parts показываются отдельно (7/8 пар не превращаются в 7/8 правильных заданий).

Гарантия скрытого решения относится к API занятия и его ошибкам. Общая
авторизованная библиотека позволяет видеть ответы при просмотре вопросов;
режим экзамена и роли пользователей не добавляются.

Неверный ответ выделяется красным и словами/значком, верный — отдельным
состоянием. Нельзя полагаться только на цвет. Для пар: выбрать слева → выбрать
справа, отменить пару. Для порядка: нажимать слова, возвращать слово, очищать
последовательность. Эти действия доступны на touch-экране и с клавиатуры;
drag and drop не обязателен и не входит в первую версию.

Все новые подписи и ошибки имеют PL/EN/RU переводы. Авторизация, Origin/CSRF,
изоляция истории, удаление и защита файлов сохраняются.

## Приёмка и выпуск

Проверить схемы, серверную проверку, миграцию 0005→0006, старые снимки,
генерацию и её три попытки, редактирование, полный API-путь пяти типов,
доступность решений только после ответа, историю и повторение.
Браузер: desktop/mobile, селектор запуска, обе цели генерации, неподходящие
типы с причинами, все пять типов, неверные ответы, перезагрузка,
возврат к теме, PL/EN/RU, клавиатура, отсутствие переполнения и ошибок консоли.
Полный `sh scripts/check.sh`: pytest, Vitest, Playwright, Ruff/format,
ESLint, сборка, Bandit и Semgrep. Обязательных новых зависимостей нет.

Перед будущим выпуском: отдельная полная резервная копия; миграция проверяется
на копии данных. Сохранность старых таблиц/JSON и файлов проверяется отдельно
от ожидаемого добавления колонок и номера миграции. `.env`, настройки Traefik
и Docker-том сохраняются. Коммит, push и выпуск относятся к этапу реализации,
а не к подготовке этого плана; подтверждение пользователя требуется до них.

## Перемешивание (дополнение пользователя)

При каждом новом занятии и повторе ошибок перемешиваются вопросы и варианты выбора ответа. Правильные индексы переотображаются, включая несколько правильных ответов. Начатое занятие, сохранённая история и ответы при повторной загрузке сохраняют свой порядок. Сохранённые вопросы в библиотеке не изменяются.
