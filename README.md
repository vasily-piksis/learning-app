# Учиться

Небольшая семейная библиотека: **предмет → темы → карточки**. Учебные PDF, фотографии и субтитры YouTube сохраняются, OpenAI создаёт карточки по выбранным темам, а занятия и объяснения остаются в личной истории.

FastAPI + SQLite + React/TypeScript + shadcn/ui. Один контейнер, постоянный volume, без Redis и отдельного сервера базы. Node.js нужен только для сборки интерфейса.

## Запуск через Docker

```sh
test -f .env || cp .env.example .env
# Добавьте OPENAI_API_KEY в .env. Локальный адрес по умолчанию: http://localhost:8080
docker compose up --build -d
docker compose exec app python -m app.cli create-user daughter --name 'Дочка'
```

CLI дважды запросит пароль скрытым вводом (минимум 10 символов). В приложении нет регистрации, стандартного логина или предустановленного пароля. Откройте [локальное приложение](http://localhost:8080) и войдите. Для дополнительного аккаунта выполните ту же команду с другим логином. Логин: латинские буквы, цифры, `.`, `_`, `-`.

```sh
docker compose exec app python -m app.cli reset-password daughter
docker compose logs --tail=100 app
```

Сброс пароля отзывает все сессии аккаунта. Библиотека общая, занятия и обсуждения доступны только своему пользователю.

## OpenAI

В `.env` задаются:

| Переменная | Значение |
| --- | --- |
| `OPENAI_API_KEY` | Серверный API-ключ; никогда не попадает в браузер |
| `OPENAI_MODEL` | По умолчанию `gpt-6-luna`, модель с vision и Structured Outputs |
| `APP_PORT` | Порт на loopback хоста, по умолчанию 8080 |
| `APP_ORIGIN` | Точный адрес, который открывается в браузере, без завершающего `/` |
| `COOKIE_SECURE` | `false` только для локального HTTP; `true` для HTTPS |

Подписка ChatGPT не оплачивает API. Распознавание, генерация и объяснения вызывают оплачиваемый API. Переворот готовой карточки и проверка сохранённого теста обходятся без модели. Без ключа библиотека, логин и готовые занятия работают; AI-задача показывает понятную ошибку и допускает повтор после настройки ключа.

Все три типа ответов используют **Pydantic + Responses API `responses.parse(text_format=...)`**. Приложение отдельно проверяет отказ, неполный ответ, тему, формат, варианты и ссылки на страницы. Успешное соблюдение схемы не гарантирует фактическую точность: перед сохранением вопросы открываются как редактируемые черновики.

Оригиналы остаются в теме. Для PDF модель получает по одной странице как `input_file`, включая рисунки; фотографии передаются как `input_image`. Распознанные страницы кешируются. Пустые страницы отмечаются и исключаются из источников карточек; предупреждения о распознавании видны рядом с документом. Неудачные страницы можно повторить без повторного распознавания уже сохранённых.

## YouTube

Внутри темы откройте «Материалы» → «Урок из YouTube» и вставьте HTTPS-ссылку. Приложение определяет исходную дорожку субтитров без перевода. Если исходный язык неоднозначен, выберите одну из доступных дорожек. Поддерживаются обычные ссылки, `youtu.be`, Shorts, live и embed. Список воспроизведения не импортируется. Субтитры получаются без ключа YouTube; ручной загрузки субтитров и скачивания аудио/видео нет.

Текст и временные метки остаются в SQLite и в сохранённом JSON в `/data/files`. Ссылка на то же видео и язык в одной теме не добавляется повторно. Повтор после ошибки продолжает существующую задачу; если текст уже сохранён, сетевой запрос не повторяется. Полученные субтитры можно скачать из списка материалов.

Вопросы используют обычную генерацию, черновики, тесты и объяснения. Вместо номера страницы источник показывает временную метку и открывает соответствующий момент YouTube. Автоматические субтитры отмечаются предупреждением. Перед сохранением проверяйте вопросы: субтитры могут содержать ошибки и не передают содержание рисунков без речи.

Получение реализовано через [youtube-transcript-api](https://github.com/jdepoix/youtube-transcript-api). YouTube может блокировать IP сервера; у видео могут отсутствовать субтитры нужного языка или доступ к ним. В этих случаях материал показывает ошибку и кнопку повтора; приложение не подменяет субтитры придуманным текстом. Язык автоматически не заменяется другим.

Лимиты: 100 000 символов, 10 000 непустых фрагментов, временные метки до 24 часов; превышение завершает задачу с ошибкой без обрезания. HTTP-ответы ограничены 8 МБ, запросы имеют таймауты. Миграция `0002` добавляет поля к существующей базе и сохраняет прежние документы и историю.

## Как пользоваться

1. Создайте предмет, например «История», затем тему «Древний Египет».
2. Откройте «Материалы» темы и добавьте PDF, фотографии или ссылку YouTube. Можно дополнять тему позже. Повтор того же файла или дорожки видео возвращает существующий материал с уведомлением.
3. Откройте «Вопросы» → «Создать вопросы»: выберите материалы и количество. Новые материалы отмечены и выбраны первыми. Вопросы создаются сразу для обоих способов занятий. Материалы других тем не используются.
4. Проверьте черновики, исправьте формулировки, отметьте нужные и сохраните.
5. На странице темы нажмите «Флеш-карты» или «Тест» — занятие запускается сразу по готовым вопросам. Для нескольких тем есть отдельный выбор внутри предмета. Вопросы и материалы открываются на отдельных страницах. Занятие сохраняет порядок, снимки вопросов, ответы и позицию. Продолжение доступно в истории.
6. После открытия ответа доступно «Объясни проще» и уточняющие вопросы с источниками.

Старые флеш-карты без вариантов ответа получают их при первом запуске теста: это сохраняемая задача с обращением к модели. После подготовки тест запускается, последующие занятия используют готовые варианты. Вопросы, ответы и их идентификаторы сохраняются; старые занятия используют прежние снимки. Ошибка подготовки показывает повтор, не запускает тест с частью вопросов. Если вопрос успели изменить, устаревшая задача не вызывает модель повторно: кнопка «Запустить тест заново» создаёт подготовку по актуальным вопросам.

Интерфейс доступен на польском (по умолчанию), английском и русском. Переключатель доступен до и после входа; выбор сохраняется на устройстве. Язык интерфейса не меняет язык учебного текста. Распознавание, вопросы и объяснения сохраняют исходный язык; перевод вопросов включается явно в форме создания. Оригиналы сохраняются. Уже созданные ранее русские вопросы автоматически не переписываются: новые можно создать из сохранённых исходных материалов и проверить отдельно.

Повторные генерации пропускают точные нормализованные повторы вопроса и ответа на том же языке. Близкие по смыслу формулировки проверяются вручную в черновиках.

Ограничения первой версии: PDF/JPEG/PNG/WebP, до 20 МБ на файл, 50 страниц PDF, 30 мегапикселей на изображение; 1–30 карточек при генерации и минимум одна на выбранную тему; максимум 100 000 символов источников. Ограничения не приводят к незаметному обрезанию материалов. При неготовых файлах нужно явно разрешить использовать готовые. Удаление источников не предусмотрено: так история не теряет ссылки.

Задачи выполняются одной очередью в SQLite. Закрытие вкладки не отменяет задачу. После перезапуска ожидающие задачи продолжаются; прерванные помечаются неудачными и требуют ручного повтора. Автоматического повтора запроса с неопределённым оплачиваемым результатом нет.

## HTTPS на своём сервере

Контейнер публикует порт только на `127.0.0.1`. Подключите существующий reverse proxy к `http://127.0.0.1:8080`. Для внешнего HTTPS-адреса измените `.env`:

```dotenv
APP_ORIGIN=https://study.example.com
COOKIE_SECURE=true
```

Пример Caddy на **хосте**, если прокси пока нет:

```caddyfile
study.example.com {
    request_body {
        max_size 21MB
    }
    reverse_proxy 127.0.0.1:8080
}
```

Направьте домен на сервер, откройте порты 80/443 и замените пример на свой адрес. Для прокси в отдельном контейнере `127.0.0.1` относится к самому прокси: подключайте его к общей Docker-сети и `app:8080` вместо loopback хоста. Если домена нет, для первичной проверки используйте SSH-туннель `ssh -L 8080:127.0.0.1:8080 user@server` и локальный origin из примера. Для постоянного доступа семьи настройте HTTPS.

CSRF-токен и Origin проверяются на изменяющих запросах. CORS не открыт. Сессии — случайные токены в HttpOnly cookie; в базе хранятся хеши. Пароли — Argon2. После трёх неудачных входов за 15 минут адрес клиента блокируется на 15 минут с момента третьей ошибки. Ответ — HTTP 429 с `Retry-After`; заблокированные запросы не проверяют пароль. Успешный вход сбрасывает счётчик, параллельные запросы учитываются до проверки пароля. Лимит действует в памяти одного worker и сбрасывается при перезапуске приложения.

Для reverse proxy задайте `FORWARDED_ALLOW_IPS` в `.env`: только точный адрес вашего доверенного прокси, который Uvicorn видит внутри Docker-сети. Прокси должен передавать корректный `X-Forwarded-For`. По умолчанию доверяется лишь `127.0.0.1`; без настройки несколько клиентов за одним прокси могут разделять один лимит. Не используйте `*` и не доверяйте forwarded-заголовкам от произвольных клиентов.

Страница входа и остальные страницы семейного приложения возвращают `X-Robots-Tag: noindex, nofollow`; в HTML также есть robots meta-тег. Это указание поисковым роботам. Доступ к материалам по-прежнему требует входа в аккаунт.

## Данные, обновление и резервные копии

SQLite, оригиналы и результаты находятся в volume `learning-data`, внутри контейнера `/data`. Миграции Alembic выполняются при запуске. Используется один экземпляр приложения и один Uvicorn worker. Не масштабируйте контейнеры на одной SQLite-базе.

```sh
git pull
docker compose up --build -d
```

Пересоздание контейнера сохраняет volume. **Не запускайте `docker compose down -v` для рабочей установки:** эта команда удалит учебные данные.

Согласованная резервная копия с короткой остановкой приложения:

```sh
./scripts/backup.sh /absolute/path/to/private-backups
```

Скрипт останавливает приложение, архивирует весь `/data`, затем запускает его даже при ошибке копирования. Архив содержит учебные материалы и данные аккаунтов; храните его приватно. `.env` копируйте отдельно в защищённое место.

Сначала проверяйте восстановление в **новый volume**, не поверх рабочей базы:

```sh
docker volume create learning-restore-data
docker run --rm --user 0 --entrypoint sh \
  -v learning-restore-data:/data \
  -v /absolute/path/to/private-backups:/backup:ro \
  learning-helper-app \
  -c 'tar -xzf /backup/learning-YYYYMMDD-HHMMSS.tar.gz -C /data && chown -R 10001:10001 /data'
```

`learning-helper-app` замените именем собранного образа из `docker compose images`. Для проверки запустите этот образ с восстановленным volume на отдельном loopback-порту, например 8081, с `APP_ORIGIN=http://localhost:8081`, `COOKIE_SECURE=false`, `DATA_DIR=/data`. Проверьте вход, темы, скачивание файла и историю. Только после этого переключайте рабочую установку. Не запускайте две копии на одном volume.

## Разработка и проверки

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
python3 -m venv .venv-semgrep
.venv-semgrep/bin/pip install -r requirements-semgrep.txt
npm ci --prefix frontend
sh scripts/check.sh
```

Общая проверка запускает **Ruff**, проверку форматирования, **Bandit**, **Semgrep**, **pytest**, **ESLint**, **Vitest** и production-сборку React. Эти же проверки и Docker build запускаются в GitHub Actions. Runtime-версии Python зафиксированы в `backend/requirements.lock`, npm — в `package-lock.json`.

Semgrep Community Edition установлен с фиксированной версией в отдельном окружении `.venv-semgrep`: его зависимости изолированы от runtime lockfile приложения. Отдельный запуск: `sh scripts/semgrep.sh`; другой путь к исполняемому файлу можно задать через `SEMGREP_BIN`. Проверяются `backend/app` и `frontend/src` официальными наборами `p/python`, `p/react`, `p/typescript`, `p/security-audit`; находки и ошибки сканера останавливают проверку. Правила загружаются из Semgrep Registry, поэтому нужен доступ к сети; код анализируется локально, метрики и проверка новой версии отключены. Аккаунт и облачная загрузка результатов не требуются. Данные, `.env`, зависимости, сборки и временные файлы исключены. В runtime-образ приложения Semgrep не устанавливается.

Для разработки в двух процессах:

```sh
APP_ORIGIN=http://localhost:5173 COOKIE_SECURE=false PYTHONPATH=backend \
  .venv/bin/uvicorn app.main:production_app --factory --port 8000
npm run dev --prefix frontend
```

Аккаунт создаётся отдельно: `PYTHONPATH=backend .venv/bin/python -m app.cli create-user daughter --name 'Дочка'`. Для просмотра собранного приложения одним FastAPI-процессом сначала выполните `npm run build --prefix frontend`, затем задайте origin/порт 8080.

Backend-тесты используют настоящую временную SQLite и реальные API. Только внешняя оплачиваемая AI-граница заменяется фикстурой из `backend/tests/fakes.py`; она не включается в образ и не доступна в рабочем приложении. Проверки отказа и незавершённого ответа отделены от успешной схемы. Реальный вызов Luna требует ключа и отдельного платного прогона на вашем учебном материале.
